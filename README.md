# منوچی — Digital Menu

سرویس منوی دیجیتال، سفارش‌گیری، باشگاه مشتریان و تبلیغات برای کافه و رستوران.
رابط عمومی با PHP ساده و طراحی **Material Design 3** (RTL فارسی) ساخته شده و
بک‌اند یک MVC سبک بدون فریم‌ورک و بدون Composer است.

## وضعیت

- سایت عمومی، منوی مشتری (`menu.php`)، پنل مدیریت و JSON API پیاده‌سازی شده‌اند.
- پایگاه داده MySQL/MariaDB با ۲۳ جدول و داده‌ی نمونه در `database.sql` قرار دارد.
- احراز هویت، نقش‌ها، جداسازی داده‌ی کسب‌وکارها، CSRF، محدودیت نرخ درخواست،
  آپلود امن تصویر و گزارش امنیتی فعال است.
- درگاه پرداخت واقعی وجود ندارد؛ اشتراک‌ها و پرداخت‌ها دستی ثبت/نمایش داده می‌شوند.

## پیش‌نیازها

- PHP **8.1 یا بالاتر** (تست‌شده روی 8.5) با افزونه‌های
  `pdo_mysql`, `mbstring`, `openssl`, `fileinfo`, `json`
- MySQL 5.7+ یا MariaDB 10.3+
- Apache با `mod_rewrite` (توصیه‌شده) یا nginx

## راه‌اندازی

1. فایل محیط را بساز و کلید برنامه را تنظیم کن:

   ```bash
   cp .env.example .env
   php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
   ```

   مقدار خروجی را در `.env` جلوی `APP_KEY=` بگذار. `APP_KEY` برای امضای URL
   فایل‌ها و هش کردن IP استفاده می‌شود؛ در محیط عملیاتی حتماً مقدار واقعی داشته باشد.

2. **وارد کردن پایگاه داده (دستی):** فایل `database.sql` را در phpMyAdmin
   (تب Import) انتخاب و اجرا کن. این فایل خودش دیتابیس `digital_menu` را می‌سازد،
   جدول‌ها را به ترتیب وابستگی حذف/بازسازی می‌کند و داده‌ی نمونه را می‌ریزد.
   هیچ کد یا اسکریپتی این فایل را به‌صورت خودکار اجرا نمی‌کند.

3. پوشه‌های `storage/logs` و `storage/uploads` باید برای PHP قابل نوشتن باشند.

4. اجرای محلی:

   ```bash
   php -S 127.0.0.1:8091 -t C:\xampp\htdocs
   ```

   سپس `http://127.0.0.1:8091/digital-menu-latest/login.php` را باز کن.
   روی XAMPP کافی است پوشه را زیر `htdocs` بگذاری. سرور داخلی PHP فایل
   `.htaccess` را نمی‌خواند؛ فقط برای توسعه‌ی محلی است.

> هشدار: `database.sql` جدول‌های موجود را حذف می‌کند. روی دیتابیس دارای داده اجرا نکن.

## حساب‌های نمونه

همه‌ی رمزها موقت هستند و در اولین ورود باید تغییر کنند (`must_change_password=1`).

| نقش | ورود | رمز |
| --- | --- | --- |
| مدیر پلتفرم | `admin@monochi.ir` | `Admin@1404` |
| مالک کسب‌وکار | `owner@monochi.ir` | `Owner@1404` |
| کارمند | `staff@monochi.ir` | `Staff@1404` |

## مسیرها

| مسیر | توضیح |
| --- | --- |
| `/` و صفحات `.php` | سایت معرفی، تعرفه، تماس، ورود، ثبت‌نام |
| `menu.php?slug=cafe-monochi` | منوی عمومی مشتری + ثبت سفارش |
| `admin/index.php` | پنل مدیریت (مسیرها با PATH_INFO: `/products`, `/orders/12`, …) |
| `api/index.php` | JSON API (`/health`, `/menu/{slug}`, `/orders`, `/ads`, `/contact`, …) |
| `media.php?f=…&e=…&s=…` | سرو تصویر آپلودشده با URL امضاشده و منقضی‌شونده |
| `logout.php` | خروج، فقط با `POST` + CSRF |

پنل مدیریت شامل داشبورد، محصولات، دسته‌بندی‌ها، منو و میز، سفارش‌ها، مشتریان،
جوایز، کمپین‌ها، کاربران، تنظیمات و — برای مدیر پلتفرم — کسب‌وکارها، اشتراک‌ها،
پیام‌های تماس و گزارش امنیتی است.

## نقش‌ها

| نقش | دسترسی |
| --- | --- |
| `super_admin` | همه‌چیز؛ برای مدیریت هر کسب‌وکار باید از `/tenants` وارد آن شود |
| `owner` | منو، محصولات، سفارش‌ها، مشتریان، جوایز، کمپین‌ها، کاربران و تنظیمات کسب‌وکار خودش |
| `staff` | مشاهده و به‌روزرسانی سفارش‌ها، مشاهده‌ی منو و گزارش‌ها |

هر کاربر عادی همیشه به `tenant_id` خودش محدود است؛ شناسه‌ی کسب‌وکار از درخواست
خوانده نمی‌شود.

## ساختار

```
config/app.php          بوت‌استرپ، ثابت‌ها، url()/asset()/e()
config/config.php       تنظیمات env (db, session, uploads, security)
app/bootstrap.php       اتولودر App\، .env، مدیریت خطا
app/Core/               Database, Auth, Session, Csrf, RateLimiter, Router, …
app/Models/             مدل‌های جدول‌ها
app/Services/           OrderService, LoyaltyService, UploadService
app/Controllers/Admin/  کنترلرهای پنل
app/Views/              قالب‌های پنل و منوی عمومی
admin/index.php         فرانت‌کنترلر پنل
api/index.php           فرانت‌کنترلر API
assets/                 CSS/JS طراحی Material 3
storage/                لاگ‌ها و آپلودهای خصوصی
database.sql            اسکیمای کامل + داده‌ی نمونه
SECURITY.md             مرور امنیتی و توضیح دفاع‌ها
```

## آدرس‌دهی

همه‌ی لینک‌ها از `url()` و `asset()` می‌آیند و مسیر نصب از `DOCUMENT_ROOT` نسبت
به ریشه‌ی پروژه محاسبه می‌شود. بنابراین سایت هم در ریشه‌ی دامنه (`/`) و هم در
زیرپوشه (`/digital-menu-latest/`) کار می‌کند — از جمله از داخل `/admin/` و `/api/`.

## امنیت

خلاصه‌ی دفاع‌ها و نتیجه‌ی آزمون‌ها در [`SECURITY.md`](SECURITY.md) آمده است:
کوئری‌های آماده‌شده، خروجی escape‌شده، CSRF، نشست سخت‌شده، کنترل دسترسی و
جداسازی چندمستأجری، آپلود امن، URL امضاشده و محدودیت نرخ برای ورود و API.

پیش از انتشار: `APP_KEY` واقعی بگذار، HTTPS را فعال کن، رمزهای نمونه را عوض کن،
و مطمئن شو `database.sql` از دسترس وب خارج است (`.htaccess` این کار را می‌کند).
